# Security

## Reporting

Report a vulnerability privately through GitHub's "Report a vulnerability" form on this repository (Security tab). Do not open a public issue. Include the version or commit, what an attacker needs, and a reproduction if you have one. Expect an acknowledgement within a week.

## Scope

wormhole assumes honest, enrolled devices on a private network (Tailscale); see the fault model in docs/design.md. Participants do not lie, but they crash, run buggy builds and relay untrusted text, so the checks below still matter. Identity is per tailnet node: the hub cannot tell operating-system accounts on one machine apart, so each machine must be used by one person or by accounts that all trust each other. In scope:

- The hub accepting a connection it cannot identify, or letting one connection act for a session, user or machine it does not own.
- Lease bypass: a stale fencing token accepted, a lease released or granted by a non-holder.
- Text from another session reaching a model without being wrapped, cleaned and length-limited, or able to pass as the local user's instruction.
- File contents, prompts or message bodies leaking into the event log, activity page or hook output beyond what the design states.
- The daemon's loopback HTTP endpoint or Unix socket being usable from a browser or another local user.
- Hooks blocking work when the hub or daemon is down. They must fail open; a protected path is denied only while the hub answers and reports another holder, and an edit whose path is too long to check only while the hub answers.

- Delegation (docs/adr/0001-delegation.md): a delegated task reaching a session at a permission level the receiving owner's local policy did not grant; an `allow` answer outside an open bypass contract, outside its paths and argv exact command patterns, for a denylisted path or command, or while the hub is stale; a request from a machine whose daemon did not advertise the capability; delegation events visible to a third machine or task text on the activity page.

Out of scope: an enrolled participant lying on purpose (no Byzantine fault tolerance: false activity, hoarding leases, a dishonest hub), other accounts on an allowed machine (the hub treats them as that machine), denial of service from an enrolled peer, a compromised device that was admitted to the tailnet, and anything requiring the hub to be exposed to the public internet (unsupported). The same behaviour caused by a bug, such as an agent loop, is in scope.

## Threat model notes

Covered:

- Transport: participants trust each other, the network path is not trusted. The hub serves plaintext only on loopback or a Tailscale address, where WireGuard encrypts the path, and the daemon sends plaintext only to such an address or a `*.ts.net` name. Elsewhere TLS is required: the hub serves `wss://` and `https://` with rustls (no OpenSSL), and the daemon verifies the certificate against the system roots; there is no option to skip verification. A renewed certificate is loaded on SIGHUP. Tests cover a verified round trip and rejection of an untrusted, expired or misnamed certificate.
- Identity comes from the network (`tailscale whois` on the peer address), never from the payload. It names the tailnet login and node, not the operating-system account. whois runs once for every new connection or HTTP request and is never cached, so a tailnet address reassigned to another node is identified afresh; at most four whois processes exist at once (others wait; each is killed after three seconds, and its slot is freed only once it has exited, even if the client has gone), so requests cannot make the hub spawn processes without limit; if whois fails or returns no user and node, the connection is refused (identity fails closed, unlike hooks). Static identity is for tests; the hub refuses it unless bound to loopback and rejects non-loopback peers.
- Relayed text is cleaned before it reaches a model: control characters and all Unicode format (Cf) characters are removed, including the tag block U+E0000 to U+E007F used to smuggle hidden instructions, variation selectors, U+00AD, U+034F and U+180E. U+2028, U+2029 and U+0085 are treated as line breaks. `<`, `>` and `&` are escaped so a body cannot close its wrapper. The hub refuses a session id, repo, path, user or scope containing any of these characters, so a single-line name cannot break into forged lines. The daemon also folds every name it shows a model to one line, so a name stored before this check, or sent by an older hub without it, cannot either; only a message body keeps its line breaks.
- A session id is bound in the hub database to the first peer that registers it, and stays bound after the session ends or times out; another peer cannot re-register it. A timed-out session's leases are released. A message to a session records the recipient's user and machine when it is sent, and only that peer can receive it, before or after the session expires.
- Each hub connection has a bounded outbound queue. A consumer that cannot keep up is disconnected (and resumes from its cursor on reconnect); replay waits at most 2 s for queue space and reaches back at most 100,000 events.
- Every hub route checks that the Host header names the hub (its listen address, or a name given with `--hostname`), against DNS rebinding. The activity page also refuses a foreign `Origin` or a cross-site `Sec-Fetch-Site`, and never shows fencing tokens.
- The daemon's loopback hook endpoint requires `Authorization: Bearer <token>`, compared in constant time. The token is 32 random bytes from `/dev/urandom`, kept in `hook-token` (mode 0600) in the daemon's private directory; `wormhole install` prints it for `.claude/settings.local.json`, which is not committed. The endpoint also rejects any `Origin` header and any `Host` that is not loopback, so other local users and browsers cannot drive it (other local users can still reach the hub directly; see below). Headers and token are checked before any of the body is read. No body size is refused with 413 (which Claude Code would treat as a non-blocking error, letting the edit skip the check): the body is reduced while it streams in, keeping only strings up to 4 KiB, so the path is recovered and the normal deny or warning applies to edits of any size. A body that cannot be parsed, is still over 1 MiB once reduced, or exceeds 1 GiB is answered with a PreToolUse deny that says why, and so is an edit whose path is over 4 KiB or whose repo-relative path is over 512 bytes, which cannot be checked, if the hub answers (otherwise the edit goes ahead with the stale note, as any edit does).
- The daemon's runtime directory is checked with `lstat` before use: it must be a real directory (not a symlink), owned by the effective uid (`geteuid`), with no group or other access. The socket path is never followed if it is a symlink or replaced if it is not a socket. Each Unix socket peer's uid must equal the daemon's effective uid. (The other-uid case is tested as a rule, since tests have no second account.)
- Edit paths are resolved on disk before leases and protected globs are applied: symlinks and `..` are followed, the result must lie under the canonical repository root, and on a case-insensitive filesystem protected globs match regardless of case. A symlink that leads out of the repository is treated as outside it.
- The hub database holds message bodies. It is created with mode 0600 before SQLite opens it (not following a symlink), its `-wal` and `-shm` files are set to 0600, and a failure to set modes is an error. A missing parent directory is created 0700, and a parent directory other users can write to is refused.
- A lease transfer applies the same overlap check as an acquire, in one transaction: it is refused if the recipient would overlap a lease held by a third session. The grantor's own leases inside the transferred scope are released with it, each with a `lease.released` event; if the grantor also holds a broader lease that overlaps the scope, the transfer is refused and the grantor is told to narrow or release that lease first, so no lease is dropped silently. Containment is conservative: a plain scope names a file and a directory scope ends with `/`; a glob covers a directory scope only if it is recursive (`**` or `<dirs>/**`, never `a**`) over it, so a directory lease is never released by a narrower glob.
- Lease TTLs from clients are clamped to 100 ms through 4 hours, and expiry arithmetic saturates within SQLite's i64 range, so a huge or wrapped TTL cannot overflow or create a lease that never expires.
- Length caps are applied to the escaped output, so escaping cannot expand text past the cap. A block larger than the whole context budget is truncated rather than withheld.

Not covered (accepted for this slice; details in docs/design.md under "Security notes"):

- Identity is per tailnet node, not per operating-system account. Any account on an allowed machine can connect to the hub directly (WebSocket, HTTP API, activity page), skipping the daemon and its uid and token checks, and the hub treats it as that machine: it can read messages addressed to the machine's sessions, register sessions, take and release their leases, and send as them. Use wormhole only on single-user machines or machines whose accounts all trust each other.
- The hub accepts a second connection with the same identity alongside the first. Session ids are bound to the machine name, so after a machine rename, new connections cannot receive messages addressed to its earlier sessions or reuse those session ids. Existing connections keep their original identity until they disconnect.
- Processes running as the same user, including the agent's own shell, can read the hook token and use the daemon socket.
- While the daemon is down, another local user could listen on the fixed hook port and receive hook requests.
- Text relayed by a trusted agent may carry instructions it read elsewhere. It is wrapped, cleaned and labelled as data, and the user's permission prompts stay in force, but the receiving model can still follow it. Under a delegation level the owner granted this is the point of the grant: at `scoped-bypass` and `full-bypass` a relayed injection, or a compromised trusted sender, acts without a prompt inside the contract until it ends (a granted test command runs code the sender can write into the granted paths; `full-bypass` is a shell on the receiving machine for the contract's life). Grant bypass levels only to senders whose machine you would hand your keyboard to.
- The delegation denylist is defence in depth, not a boundary: its text screen over a contract's text is a tripwire (free text can be reworded) and its argv checks are examples, since a list of dangerous programs cannot be complete. At `scoped-bypass` the boundary is the contract's command allowlist: exact argv patterns whose program is on a short safe list (`ls` and `stat` (list and describe files), `cat`, `head`, `tail` and `wc` (read files), `grep` and `diff` (search and compare), `cut`, `tr`, `basename`, `dirname` and `realpath` (pure text and path tools), and `pwd`, `echo`, `true` and `false` (print or exit). Each is on the list because none has an option that runs another program or writes a file. Left out on purpose: `rg` (`--pre`), `sort` (`--compress-program`, `-o`), `uniq` (writes its second operand), `rustfmt` (writes files outside any scope), shells, interpreters, `env`, `xargs`, `find`, `awk`, `sed`, `make`, `npx`, `npm` and `sudo`. `git` and `cargo` are not defaults: the owner may add them to `safe_programs`, and then they are usable only as `git|cargo <literal subcommand> [listed options]` (git: `status` only while the denylist is on, plus `log`, `diff` and `show` when it is off, with `--oneline --stat --name-only --name-status --short --porcelain --cached --staged --no-color`; cargo: `test`, `check`, `build` with `--lib --bins --tests --doc --all-targets --workspace --release --locked --offline --quiet -q --no-fail-fast`); `cargo test` and `cargo build` still run project code (tests, build scripts), which is the owner's choice. While the denylist is on, git is usable only as `git status`: `log`, `diff` and `show` can print the contents of a denied path (`git show HEAD:secrets/x`, `git log -p -- secrets/`) even though each operand passes the path check, so they are available only with the denylist module off. A Bash operand that is an existing directory is allowed only for `ls`, `stat`, `realpath`, `basename` and `dirname`, since `grep -r` or `diff -r` would read denied files below it. `cargo` refuses a `+toolchain` token anywhere. If the owner tightens the policy, an open contract is cut to the new time and step limits at its next bypass answer and closes (reason `policy tightened`) if either is already used up. Any other program added through `safe_programs` is the owner's responsibility: add only programs with no exec, config or alias escape.), commands with quotes, backslashes, glob or brace characters or `~` never match, and anything else gets the normal prompt. Edits are bounded by the contract paths and per-call path checks; at `scoped-bypass`, every operand of an allowed command is read as a path and must be inside the repository (symlinks followed, none dangling), not protected and not denylisted; options containing `=` are refused; the allow also needs the session's repository to equal the contract's, no `dangerouslyDisableSandbox`, an audit line written first, and the policy file still granting the contract at its level (a narrowed policy closes the contract). Not done: a per-sender rate limit on `Delegate`, a result posted on TTL or step close, lease events from a hand-off being visible to every machine, and `user@machine` grants being ambiguous for a login that contains `@`. At `full-bypass`, Bash is not bounded by any parser: it is a trust decision about the sender and the denylist is a speed bump. Contracts live in daemon memory; the kill switch (`wormhole delegation revoke`) closes them.
- Edits through shell commands are not checked against leases or protected paths.
- No rate limits, and no pruning of the hub's log.
